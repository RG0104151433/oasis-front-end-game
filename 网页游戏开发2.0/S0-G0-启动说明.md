在 G0 放行闸前，完成《设计运行规划》S0 阶段的全部入场动作，使项目从“设计规划”进入“五轨并行设计”（S1）。本说明是交给执行 agent 的需求文档，执行 agent 只需按第 4 节产出清单创建文件并填写内容，不得修改规划文档本身。

## 2. 范围

### 2.1 包含

1. 建立 DDP（设计定义包）目录骨架：`网页游戏开发2.0/设计定义包/`；
2. 创建《决策记录》模板 `01-决策记录.md`，并登记 Q3、Q4 为“已同意默认”；
3. 创建《设计定义包索引》`00-索引与状态.md`，登记 00–09 各文件的角色、主责轨、会签轨；
4. 创建资料快照 `02-资料快照与问题清单.md`，记录当前仓库路径、文档版本、已知问题清单；
5. 创建 Q1/Q2/Q5/Q6 的待决裁定表 `03-Q1Q2Q5Q6待决裁定.md`，列出选项、影响与推荐结论，等待决策人签字；
6. 更新《设计运行规划》版本记录中“Q3/Q4 已登记为已同意默认”的状态（仅一行，不改其他内容）。

### 2.2 不包含

1. 不填写 04–09 各设计域文件（A/B/C/D/E 轨正式工作包），这些在 G0 通过后启动；
2. 不修改 `小学期网页开发/` 下任何 JS/CSS/HTML；
3. 不修改根基剧本、纯剧情版、增量数据契约；
4. 不裁定 Q1、Q2、Q5、Q6 的最终结论（只整理成可签字的待决表）；
5. 不写 `story_config.js`、`engine/`、`store.js` 或任何故事编码。

| 约束 | 说明 |
