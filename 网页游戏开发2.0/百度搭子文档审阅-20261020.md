## 三、前端游戏开发自洽性审查与完整指南缺口

### 3.1 必须先修正的规则冲突

**C01 / 阻塞 / 确认冲突：第六结局被错误地依赖于第五结局。**

- 依据：BASE §2.3 写“第零线完成＋无排除项”；ZERO §4.4、§5.2 却要求 `allOf: ['fifth_signature_done','witness_release']`；根基方案 §4.4.1、§5.1 明定独立解锁、同层并存。
- 影响：agent 会把独立隐藏线实现为“第五之后才能进入第六”，改变既定玩法。
- 修正：第六解锁独立判断 `zero_arc_complete && !sixth_arc_sealed && !buyoutBinding && !ally_maze_leave`；将原 allOf 移回双达成回顾，并追加“两结局均 seen”的条件。补测试：仅 Z、仅第五、两者都有、任一排除项命中、旧档无封条但排除项已存在。此处修正应落在 ZERO 和回归规范，根基原件不改。

**C02 / 阻塞 / 确认冲突：M 线互斥组使正常流程无法同时满足。**

- 依据：KM §3.2、§4.2 写 M2 追问→M3→M4 收下/拒收；§3.3 却要求 pressed/token/refused 同一周目只成立其一。R1 §5 的持证存档又同时包含 pressed 与 token。
- 影响：若真实施“先写者胜出”，M2 写 pressed 后就不能获得 token；若按顺序都写，报告又违反所谓三值互斥。
- 修正：pressed 是是否追问的路径状态；token/refused 是徽记选择，两者互斥但可与 pressed 并存。回看须有“收下/拒收/尊重沉默”三态，不能无 token 都当未追问。重做与此相关的验收。

**C03 / 阻塞 / 确认规格冲突、实现待复验：穹顶终局被用旧 X 线内容替代证明。**

- 依据：BASE §3.1–3.3、§6.2 要求移出 `obj_dome`、独立 3–4 分钟演出、迁移 dome reviews、`dome_line_played` 防重播及旧档兜底。MAP §4.8 / AI §8 的 C2 主要列已有交易/收购/成就、把该批次视为完成。

- 修正：补逐项表“需求→真实代码位置→状态/资源→验收用例→证据”。未覆盖项恢复任务；C2 可保留为历史判断但标注证据不足，不能作为跳过全部终局重构的依据。

**C04 / 高 / 确认冲突：入口进度与最新交接不一致。**

- 依据：HUM §1、MAP §3、AI §3 仍写 K/M、D/N/F 未落码；R1 声称 K/M 验收通过，H2 声称 D/N/F 已落码但动态未测。

### 3.6 建议修正顺序与“足够自洽”的退出条件

1. **先统一规则**：优先处理阻塞级 C01/C02/C03，并在建立状态/事件协议时一并处理 C04–C06；给出六结局公式、M 线合法状态组合、穹顶改动逐项映射；把未获确认的改法明确留在决策记录。
2. **再核工程版本与可达性**：定位真实工程并绑定哈希；验证 N 回访/M→N、F→D 两种顺序、E 的 bond=0 支路与 X4 依赖、第零线重入与超时。根据证据回填状态页，不重做已通过且版本吻合的工作。
3. **补统一执行协议**：事件/状态字典、能力矩阵、资源与地图映射；补 X4/穹顶/P0-1/第五协议的依赖闭环。
4. **强化验收并补证据**：保存基线、准备合法存档夹具、执行路径测试；批次 2 完成动态验收后才产出正式通过报告，规则变更涉及的 K/M 部分重新验收。
5. **最后迁移与收敛**：稳定文件名、修链接；隐藏副本与空会话目录当前已不存在，不再执行删除；收敛四处动态进度、G5 完整定义与决策记录的重复维护，保留唯一正文与历史记录。

退出条件：同一需求只有一个当前权威定义；每个触发器都有确定的前置、状态写入、出口、回看与中断恢复行为；六结局及跨线关键组合都可沿合法游玩路径验证；每条完成声明绑定代码版本与可复现证据；新 agent 能从入口识别当前状态、选择正确任务、只读必要依赖并按验收标准交付。满足这些条件后，可称“剧情增量开发指导自洽”；完整游戏开发指南还需补齐 §3.5 的全局工程章节。
