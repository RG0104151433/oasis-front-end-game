# THE OASIS · 05 六结局规则真值表

- 版本：v1.0（正式 DDP）
- 日期：2026-11-13
- 状态：正式 DDP；由 B 轨草稿 v0.1 升级
- 主责：B 轨（结局/规则/状态）

- 依据裁定：Q1=A（设计全量、实现分期）、Q2=首发可玩第零线、Q5=A

## 1. 六结局定义

| 结局 id | 名称 | 前提 | 排除项 | 兼得 | 优先级 |
|---|---|---|---|---|---|
| `inherit` | 个人继承 | 三钥 + `palace_memory` 选择继承 | 无 | seen/done | 1 |
| `dome` | 穹顶托管 | 三钥 + `palace_memory` 选择穹顶 | 无 | seen/done | 2 |
| `public_energy` | 公共能源 | 三钥 + `palace_memory` 选择公共能源 + 现实证据（D/F 线） | 无 | seen/done | 3 |
| `charter` | 玩家公约 | 三钥 + `palace_memory` 选择公约 + K 线署名 echo clue | 无 | seen/done | 4 |
| `fifth_protocol` | 第五协议 | `fifth_arc_completed`（G1 预留） | 四协议 | — | 5 |
| `sixth_protocol` | 第六协议 | `sixth_arc_sealed`（G1 预留） | 四协议 | — | 6 |

> 第零线（`zero_line`）不是结局，是第五协议的前置维护窗口；Q5=A 同周目可再入、不写失败态。

## 2. 状态字段

每个结局在存档中的状态生命周期：

| 状态 | 含义 |
|---|---|
| `entered` | 进入宫殿并看到该结局选项 |
| `chosen` | 点击该结局 |
| `completed` | 播放完结局演出并写入 reviews |
| `eligible` | 满足 requirements |
| `seen` | 已看过结局文本（回看） |
| `done` | 该结局已达成（不可再作为新达成记录） |

## 3. 旧档补算

| 字段缺失 | 默认行为 |
|---|---|
| `fifth_arc_completed` | 视为 false；第五协议不可达成 |
| `sixth_arc_sealed` | 视为 false；第六协议不可达成 |
| `zero_backup_tape` | 视为缺失；第零线维护窗口未关闭 |
| `kira_signature_echo_public` / `kira_signature_echo_sealed` | 视为未选择；charter reviews 缺一条实体条款 |
| `morrow_witness_token` | 视为未获得；M 线徽记缺失 |

补算统一在 `Store.normalizeProgress` 层完成，引擎不直接读缺失字段。

## 4. 红线

- 第五/第六/第零线只能新增 conditions，不改四协议 `requirements`；
- 不向 `inherit`/`dome`/`public_energy`/`charter` 的 requirements 写入任何新字段；
- 结局数量不写死；终局选择、结局回放、结局成就都从 `cfg.endings` 生成；
- 信物槽/隐藏结局入口用列表数据驱动，不做“四个固定按钮”。

## 5. 第零线维护窗口（Q5=A）

| 子问题 | 裁定 |
|---|---|
| 同周目能否再入 | 是：回到 `finale_transition` 仍可再选；倒计时耗尽后重进 |
| 是否写“错过/失败/次数”状态 | 否：不写 `zero_missed`、`sixth_arc_sealed` |
| 通关后是否继承 | 否：一周目错过，二周目不保留磁带/已看结局/封条 |
| UI 是否提示 | 否：隐藏线完全不提示，不给“维护窗口已关闭”反馈 |
